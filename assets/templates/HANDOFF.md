# HANDOFF.md — 交接日志（追加式）

> 用途：任何进入 git 提交的源码改动，提交前在下方固定注释之后插入对应交接记录，最新在最上。
> 换会话/换模型后，新接手者读最近 1-3 条即可续上。
>
> 如果这个项目在装这套体系之前已经有自己的开发日志、格式跟这里不兼容（比如按时间从旧到新往下追加、自由格式而不是下面按有无 Task 分档的模板），**不要另存一个归档文件**——把旧内容原样接到本文件最下方，中间插入这行固定文字（逐字复用，`docs/WORKFLOW.md` 的 A4 巡检脚本靠它判断日期序检查该在哪里停下）：
> ```
> ---
>
> <!-- 归档分界：以下内容归档自旧格式历史记录，不适用上方"新记录插最上面/五段结构"的约定 -->
>
> ## 历史记录（<旧文件的日期范围>，旧格式，仅供追溯，不再追加）
> ```
> 归档段落本身不做任何整理或重写，原样保留；新记录一律只加在本文件最上方、这条分界线以上。

---

## 模板

有 Task：只记结论与原因，详细方法和数据放在 report 一处，日志引用它。

```markdown
## <YYYY-MM-DD HH:MM> — <任务简称>
- **改了什么**：1～2 句结论
- **为什么**：
- **风险/未完成**：
- **报告**：[验证报告](tasks/<任务目录>/report.md)
```

无 Task：保留完整五段。若验证需要表格、多组数据或方法说明，应先立 Task，不把详细证据塞进日志。

```markdown
## <YYYY-MM-DD HH:MM> — <任务简称>
- **改了什么**：
- **为什么**：
- **验证**：实际验证结果；规格同步结果：已同步（链接与要点）／无需同步（具体原因）／待同步（缺项与下一步）
- **下一步**：
- **风险/未完成**：
```

两档都完整保留「为什么」。有 Task 的规格同步结果只写 report，HANDOFF 引用报告；无 Task 写在上方「验证」段。待同步不得宣称全部收口。报告结论被纠正时，在引用它的旧摘要附近追加“YYYY-MM-DD 修订：见报告修订记录”的链接，保留原文、原日期，不重排历史条目；同时检查任务索引与规格引用。
