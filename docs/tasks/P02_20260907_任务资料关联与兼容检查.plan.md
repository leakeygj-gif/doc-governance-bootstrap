## 目标

让新任务的 plan/report、专用分析脚本与数据目录共用任务前缀，报告能直接说明每份资料是什么；让检查器接受实际的阶段报告组织方式，区分格式待确认与真实缺失；提供保留项目定制的只读升级预览流程。

## 边界与分工

- 工具 worker：`tools/task_pairs.py`、`assets/templates/task_pairs.py`、`tests/test_governance.py`，可新增 `tests/test_task_pairs.py`；支持明确关联、状态与验收边界、带证据的历史豁免及可复核输出。
- 文档 worker：`SKILL.md`、`README.md`、`AGENTS.md`、`references/methodology.md`、必要的新参考文档、`assets/templates/` 内任务/工作流/规则/HANDOFF 文档模板、`docs/WORKFLOW.md` 与 `docs/tasks/README.md`（登记表由主对话收口）。不修改任何脚本或测试。
- 主对话：plan/report、`docs/HANDOFF.md`、任务登记表；本任务专用的只读复核脚本可由独立审阅 worker 写入 `tools/tasks/P02_20260907_任务资料关联与兼容检查/`，汇总结果与资料清单放入 `data/tasks/P02_20260907_任务资料关联与兼容检查/`，报告直接链接。只产生必要产物，不建立空目录。
- `外部私有样本项目` 仅作为只读样本，不修改源码、文档、数据、配置或 Git 状态，不运行其业务测试、扫描或设备脚本。

## 禁区

- 不移动或批量重命名历史任务/数据/脚本；新约定面向新任务，历史按需补关联。
- 不编辑已定稿 P01 report 的数据、方法与前提；新结果只写 P02 report。
- 不安装依赖，不更新已安装 skill，不配置 hook，不 git add/commit/push，不改当前分支与已有暂存内容。
- 不用宽泛的“有完成二字”推断任务结束；不能把阶段验收尚未通过隐藏成全部完成。
- 不为使外部项目输出归零而盲目豁免。没有证据的关系和状态列为待确认，历史豁免必须明确范围、原因和来源。

## 分步计划

1. 落盘本 plan 后，分派互不冲突的工具与文档工作。
2. 任务模板加入同名前缀的脚本/数据布局、报告资料表与归档清单；共享脚本只引用，不复制；原始扫描保留原位置并记录路径/校验/保存状态。
3. 调整检查器：固定状态与验收说明分开；安全识别带补充说明的规范状态；自由状态单列待确认；同名报告和显式计划链接/阶段索引建立确定关系，不能仅按项目编号配对；历史例外采用显式配置且有来源，不从任意正文自动授权豁免。
4. 同步报告结论修订的引用检查：旧摘要可追加就近指引，保留原文；明确开发仓库、安装副本、项目生成文件三个版本层级；已有项目先只读列差异、定制和未验证项，再确认写入。
5. 用合成夹具验证漏报告、无效关联、状态歧义及无效豁免仍能暴露；运行既有回归。独立审阅者按新说明定位本任务脚本与数据，并对 外部项目只读运行检查，保留实际输出及未解决项。
6. 主对话审核，写 report、追加 HANDOFF、更新任务状态，核对 Git 边界和外部项目未变化。

## 验收点

- [x] 新任务资料能从报告一处找到脚本、输入与结果，命名前缀一致；不要求复制共享工具或原始数据。
- [x] 状态与验收边界分开，带说明的规范状态可识别，未知/矛盾状态不被当作已完成；说明完整保留。
- [x] 同名简单任务、一计划多阶段报告、复测、同项目不同任务分别正确处理；无效/歧义关联不静默放行。
- [x] 历史豁免有明确范围、原因与来源；不影响其他任务的缺失检查；无配置时不隐式豁免。
- [x] 外部项目对照输出能区分真实缺失与待人工确认，报告如实呈现剩余问题，不强求归零。
- [x] 新版规则/模板/CLI一致；既有行为回归及新增测试通过，技能结构和diff检查通过。
- [x] P01历史报告不改；外部项目与两仓库Git配置、暂存区不变；无安装、提交或推送。

## 风险与前提

- 明确链接只能证明关联存在，不能证明阶段全部完成或报告内容真实。
- 自由状态和自然语言豁免不能完全机械解释；保留人工核对，不批量改历史文件。
- 文件清单证明可定位，不等于已完成远端备份或永久保存；必须分别报告本机存在、Git跟踪与外部归档状态。
